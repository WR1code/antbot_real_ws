# AntBot + Orin Nano + H743 硬件确认清单

这份清单中的“确认”必须来自铭牌、原理图、仪表测量或实机反馈，不能只根据代码
默认值判断。

## A. Orin Nano主机

- [ ] 确认具体型号和内存容量：Orin Nano 4 GB或8 GB。
- [ ] `uname -m` 为 `aarch64`，用 `/etc/nv_tegra_release`、`/etc/os-release` 和
  `nvidia-jetpack` 软件包实际记录JetPack/L4T、Ubuntu和ROS 2版本。
- [ ] 电源额定值满足载板工作模式，插头牢固，不与电机动力直接共用细线支路。
- [ ] 已安装风扇/散热器，满载CPU/GPU温度经过测试。
- [ ] NVMe/存储容量足够，保留日志和地图空间。
- [ ] 当前用户属于 `dialout` 组，USB设备权限重启后仍正确。
- [ ] 设定唯一 `ROS_DOMAIN_ID`，有线网口和远程维护网络不会互相抢默认路由。

需要提供/记录：Orin载板型号、JetPack版本、Ubuntu版本、ROS版本、电源规格、NVMe
容量和网络接口规划。

## B. H743控制板

- [ ] FK743M2-IIT6仅从一个入口获得稳定5 V，未并联Type-C和排针两个5 V电源。
- [ ] USB-TTL是3.3 V逻辑，不是RS-232；TX接PA10，RX接PA9，GND相连。
- [ ] 使用 `/dev/serial/by-id/...`，拔插后路径不变。
- [ ] 最新H743固件已烧录，能够读取版本、Git哈希和配置指纹。
- [ ] 内部IWDG复位、远程复位和串口300 ms超时停车经过架空实测。
- [ ] 若要跨整板断电保存黑匣子，VBAT已按板卡要求提供后备电源。

排针编号和接线见
[`firmware/rs00_fk743_test/docs/WIRING.md`](../firmware/rs00_fk743_test/docs/WIRING.md)。

## C. 两条CAN总线

- [ ] 使用两只独立3.3 V逻辑CAN收发器；高压/长线环境优先隔离收发器。
- [ ] FDCAN1：PB8 RX、PB9 TX，只连接RS00，1 Mbit/s。
- [ ] FDCAN2：PB12 RX、PB13 TX，只连接MINI，500 kbit/s。
- [ ] 两条总线的H/L没有并接，也没有H/L接反。
- [ ] 每条总线完全断电后H-L约60 Ω，只有物理两端各一个120 Ω。
- [ ] CAN双绞线沿干线布置，电机支线尽量短，远离动力相线。
- [ ] 非隔离方案有可靠通信参考地；隔离方案没有错误跨接隔离地。
- [ ] USB-CAN若只用于监听，确认波特率和监听模式，不把两条总线桥接起来。

## D. RS00转向电机

- [ ] FL/FR/RL/RR的CAN ID依次为1/2/3/4。
- [ ] 四个8字节UID已经读取、记录并与实际轮位绑定。
- [ ] 每轮方向符号经过0.5度以内的小步架空测试确认。
- [ ] 四轮机械零偏实际测量，不使用全零占位值。
- [ ] 四轮最小/最大机械位置逐个测量，并留出安全余量。
- [ ] CSP模式、1 rad/s速度限制、2 A电流限制及CAN超时读回一致。
- [ ] `STEERING_ENFORCE_UID_CHECK=1`。
- [ ] 只有完成全部项目后才设置 `STEERING_CALIBRATION_CONFIRMED=1`。

## E. MINI行走驱动

- [ ] FL/FR/RL/RR的接收和发送ID均为5/6/7/8。
- [ ] 普通CAN模式，500 kbit/s，心跳超时1000 ms。
- [ ] 电机铭牌确认为24 V、150 W、10极对、105 mm轮径、直驱1:1；若不同则改配置。
- [ ] 编码器配置4096与驱动器上位机读回一致。
- [ ] 四轮正方向逐个架空确认，不能保留未经验证的 `{1,1,1,1}`。
- [ ] 四台故障码为0，安全标志为0，反馈年龄小于400 ms。
- [ ] 电流、温度、电压和速度反馈与万用表/实况相符。
- [ ] `DRIVE_ALLOW_RAW_WHEEL_COMMANDS` 正式运行时恢复为0。

## F. 动力和实体急停

- [ ] RS00和MINI动力电压分别符合各自铭牌，绝不接入FK743或Orin电源脚。
- [ ] 每个动力支路有与线径、驱动器和电池能力匹配的保险丝/断路保护。
- [ ] 主接触器和急停触点的DC额定电压、电流及灭弧能力足够。
- [ ] 实体急停无需Orin、H743、ROS、UART或CAN正常工作即可撤去动力/使能。
- [ ] 急停复位后不会自动恢复运动，必须人工重新使能。
- [ ] 电池欠压、制动回灌、浪涌和接地方案经过实测。
- [ ] Orin/H743控制电源最好保持供电，以便记录电机动力被切断的原因。

## G. 传感器和网络

- [ ] 确认使用双2D雷达还是双Livox MID360S，不同时启动两套同名 `/scan_0/scan_1`。
- [ ] 若使用MID360S，确认实际IP、主机IP、子网、帧ID和安装方向；默认候选为
  `192.168.1.12/13`，不能未经核对直接采用。
- [ ] 雷达交换机带宽、供电方式和线缆等级满足双雷达持续点云流量。
- [ ] IMU型号、串口、波特率、安装朝向和时间戳来源已确认。
- [ ] Orbbec相机型号、USB 3链路、分辨率、帧率和供电稳定性已确认。
- [ ] 如使用GNSS，确认ublox型号、天线、串口和室内无定位时的处理策略。
- [ ] 所有动态设备建立udev稳定名称，不能依赖ttyUSB编号顺序。

## H. ROS控制闭环

- [ ] 系统中只有一个节点向H743桥使用的 `/cmd_vel` 发布控制命令。
- [ ] 没有启动旧 `antbot_hw_interface` 或旧 `antbot_swerve_controller`。
- [ ] `/rs00/motor_status` 连续发布，断开UART后H743在300 ms内停车。
- [ ] 当前所有控制源保证 `angular.z=0`。
- [ ] 在启用Nav2前，真实 `/odom` 和 `odom -> base_link` 已有可信来源。
- [ ] 在启用Nav2前，H743已实现并验证旋转控制，或规划器被重新设计为完全不要求旋转。
- [ ] 两条CAN掉线、单电机掉线、串口掉线、急停和Orin进程崩溃测试全部通过。

## 当前明确未确认

当前复制的配置仍然是安全锁定状态：RS00 UID、方向、零偏、机械范围和MINI安装方向
尚未得到实机数据；实体急停和外部看门狗GPIO也尚未确定。因此本工作区现在可以迁移、
构建、查询和做架空联调，但不能作为已验收的自动导航系统。
