# 欧艾迪 MINI 智能 FOC 无刷电机驱动器

# CAN 指令详解与 DMTool 实操速查（标准 CAN 版）

> 适用对象：欧艾迪 MINI 款智能 FOC 无刷电机驱动器，使用厂商所称的 **CAN 通信控制**。
> 不适用于：CANopen 对象字典指令、RS485 Modbus RTU 指令，以及早期“命令编码在 CAN ID 中”的旧协议。
>
> 本文按《RS00 电机私有 CAN 协议指令详解》的阅读方式整理：
> **先讲帧格式，再讲字节序，再逐条给出可直接发送的例子、返回解释、成功判断和常见误区。**
>
> 全文示例统一假设：
>
> - 驱动器 CAN ID：`0x001`
> - 使用 11 位标准数据帧
> - 使用普通数据帧，不使用远程帧
> - 电机磁极对数示例：`4`
> - 多字节整数：高字节在前
>
> 实际发送前，必须把 CAN ID、波特率、心跳超时、电机磁极对数、电机最大电流和最大转速替换为你的真实配置。

---

## 0. 先看最重要的区别

欧艾迪 MINI 的 CAN 指令结构与 RS00 私有协议明显不同。

### 0.1 RS00 与欧艾迪 MINI 的帧结构区别

| 项目           | RS00 私有协议                           | 欧艾迪 MINI 本文协议                      |
| -------------- | --------------------------------------- | ----------------------------------------- |
| CAN 帧格式     | 29 位扩展帧                             | **11 位标准帧**                     |
| CAN ID 的作用  | ID 中同时编码通信类型、主机 ID、电机 ID | **CAN ID 主要用于选择驱动器地址**   |
| 命令类型的位置 | 扩展 ID 高位                            | **Data[0]**                         |
| DLC            | 通常固定 8                              | **随指令变化：1、2、3、4、5、6 等** |
| 多字节控制值   | 不同类型混合大小端                      | **本文控制值按高字节在前**          |
| 使能指令       | 有独立使能命令                          | **没有独立使能/启动命令**           |
| 控制命令返回   | 多数会返回状态                          | **控制指令本身无返回**              |
| 心跳           | 可按具体协议配置                        | **控制前必须持续发送心跳**          |

### 0.2 欧艾迪 MINI 的核心帧结构

```text
CAN ID：驱动器地址，例如 0x001
帧格式：标准帧，11 bit
帧类型：数据帧
Data[0]：控制命令
Data[1...]：命令参数
DLC：按具体命令填写
```

例如给 ID 为 `0x001` 的驱动器设置 `+1 A` 电流：

```text
CAN ID：001
DLC   ：3
Data  ：01 00 64
```

字段解释：

```text
01      电流控制命令
00 64   有符号 16 位整数 100，高字节在前
100 × 10 mA = 1000 mA = 1 A
```

### 0.3 本协议没有独立“使能”指令

欧艾迪 CAN 编程资料说明：

```text
没有专门的使能、失能、停止和启动命令。
开始控制：直接发送相应控制模式的目标值。
停止/失能：可发送电流控制值 0。
```

因此：

```text
CAN ID：001
DLC   ：3
Data  ：01 00 00
```

表示电流目标为 `0 A`，通常用于撤销输出、停止或失能。

注意：

- `0 A` 不等于电子刹车。
- 需要主动制动时，应使用 `0x08` 刹车命令。
- 需要锁住低速或静止电机时，才考虑 `0x09` 手刹命令。
- 手刹绝不能在高速运行时直接使用。

## 1. 资料范围与版本说明

### 1.1 MINI 产品手册能够确认的内容

欧艾迪 MINI 产品手册 V4.0 能确认：

- 电源范围：`DC 12~80 V`
- 持续电流：`4 A`
- 最大电流：`8 A`
- 额定应用功率：约 `200 W` 及以下
- 支持：
  - RS485 / Modbus RTU
  - CAN
  - CANopen
- 支持：
  - 电流闭环
  - 速度闭环
  - 位置闭环
  - 占空比控制
- 支持通过 USB Type-C 上位机配置
- 驱动器内部可保存 4 份电机配置
- 支持 CAN 数据监测、实时数据和心跳设置
- 再生制动会抬高母线电压，需要注意回馈能量吸收

### 1.2 产品手册没有给出的内容

用户提供的 MINI 产品手册 V4.0 **没有列出原始 CAN 帧命令表**。

本文的原始 CAN 指令格式来自欧艾迪官方 CAN 编程手册中的标准 CAN 协议。正式装车前，应确认：

```text
驱动器固件版本
当前应用类型确实为“CAN 总线”
当前使用的是本文标准 CAN 协议，而不是 CANopen
当前波特率
当前 CAN ID
当前心跳超时时间
```

## 2. 上位机首次配置流程

在使用 DMTool、USB-CAN、STM32 或 NVIDIA 主控发送指令前，先通过欧艾迪 USB Type-C 上位机完成驱动器配置。

推荐顺序：

```text
1. 接好电源、电机相线和传感器线。
2. 使用 Type-C 连接电脑和驱动器。
3. 在欧艾迪上位机中识别/学习电机。
4. 检查电机磁极对数。
5. 检查最大转速、最大电流和保护参数。
6. 将应用类型设置为“CAN 总线”。
7. 设置 CAN ID。
8. 设置 CAN 波特率。
9. 设置心跳超时时间。
10. 点击“写入应用程序配置”。
11. 等待驱动器重启。
12. 再使用 USB-CAN 进行标准帧测试。
```

重要：

> 设置为通信控制后，欧艾迪上位机主要用于监控，原上位机控制按钮可能不再作为实际控制入口。

## 3. 硬件接线与 CAN 总线注意事项

### 3.1 通讯端口

MINI 产品手册把通讯口标为 `485/CAN` 共用接口，并说明多台驱动器可并联形成多站点总线。

多驱动器总线应遵循：

```text
所有同名差分线并联
所有驱动器使用相同波特率
每台驱动器使用不同 CAN ID
尽量连接公共信号地
主干线两端设置终端电阻
支线尽量短
```

### 3.2 A、B 与 CAN_H、CAN_L

用户提供的 MINI 产品手册明确给出了端子上的 `A`、`B`、`GND`，但没有在文字中明确写出：

```text
A 究竟对应 CAN_H 还是 CAN_L
B 究竟对应 CAN_L 还是 CAN_H
```

因此不能只根据 RS485 的 A/B 命名自行猜测。

正式接线应采用以下任一方式确认：

```text
1. 查看驱动器外壳、端子丝印或对应版本接线图。
2. 查看厂商提供的 CAN 专用接线说明。
3. 向欧艾迪确认 A/B 与 CAN_H/CAN_L 的对应关系。
4. 使用厂商配套线束或转接板。
```

### 3.3 终端电阻

工程上推荐：

```text
CAN 主干最左端：120 Ω
CAN 主干最右端：120 Ω
中间节点：不重复接终端电阻
断电测 CAN_H 与 CAN_L：整体约 60 Ω
```

但若驱动器或 USB-CAN 内部已经带终端电阻，应先确认开关状态，避免并联过多。

## 4. DMTool / 通用 CAN 分析仪设置

### 4.1 必须这样设置

| 项目       | 设置                         |
| ---------- | ---------------------------- |
| 通讯模式   | CAN                          |
| CAN 波特率 | 与欧艾迪上位机中写入的值一致 |
| 帧格式     | **标准帧，11 bit**     |
| 帧类型     | **数据帧**             |
| CAN ID     | 驱动器地址，例如`001`      |
| DLC        | 按指令填写，不固定为 8       |
| Data       | 命令字节和参数字节           |

### 4.2 CAN ID 应怎样填写

假设驱动器地址为 1：

```text
推荐显示：001
有些软件显示：1
两者数值相同
```

这里的 `001` 是完整 CAN 标准帧 ID，不需要再拼接主机 ID 或通信类型。

### 4.3 不要这样设置

错误：

```text
帧格式：扩展帧
CAN ID：0300FD01
DLC：固定 8
Data：把 CAN ID 再复制进 Data
```

正确：

```text
帧格式：标准帧
CAN ID：001
DLC：按命令
Data[0]：命令类型
```

## 5. 字节序、数据类型和负数

## 5.1 16 位有符号整数：short / int16

```text
Data[1] = 高 8 位
Data[2] = 低 8 位
```

示例：

| 十进制 | 16 位十六进制 | 发送字节  |
| -----: | ------------: | --------- |
|      0 |    `0x0000` | `00 00` |
|     20 |    `0x0014` | `00 14` |
|    100 |    `0x0064` | `00 64` |
|    500 |    `0x01F4` | `01 F4` |
|   1000 |    `0x03E8` | `03 E8` |
|   -100 |    `0xFF9C` | `FF 9C` |
|  -1000 |    `0xFC18` | `FC 18` |

负数使用二进制补码。

## 5.2 32 位有符号整数：int / int32

```text
Data[1] = 最高 8 位
Data[2] = 次高 8 位
Data[3] = 次低 8 位
Data[4] = 最低 8 位
```

示例：

| 十进制 |  32 位十六进制 | 发送字节        |
| -----: | -------------: | --------------- |
|      0 | `0x00000000` | `00 00 00 00` |
|    400 | `0x00000190` | `00 00 01 90` |
|    800 | `0x00000320` | `00 00 03 20` |
|   2000 | `0x000007D0` | `00 00 07 D0` |
|   4000 | `0x00000FA0` | `00 00 0F A0` |
|   5000 | `0x00001388` | `00 00 13 88` |
|  36000 | `0x00008CA0` | `00 00 8C A0` |
|  -4000 | `0xFFFFF060` | `FF FF F0 60` |
| -36000 | `0xFFFF7360` | `FF FF 73 60` |

## 5.3 电流单位

```text
1 个数值单位 = 10 mA = 0.01 A
```

换算：

```text
发送整数 = 目标电流 A × 100
目标电流 A = 接收整数 ÷ 100
```

示例：

```text
0.2 A → 20 → 00 14
1.0 A → 100 → 00 64
-1.0 A → -100 → FF 9C
```

## 5.4 速度单位 erpm

驱动器内部速度单位是电角速度：

```text
erpm = rpm × 磁极对数
rpm  = erpm ÷ 磁极对数
```

例如电机为 4 对极：

```text
1000 rpm → 4000 erpm
4000 erpm → 1000 rpm
```

注意：

- 磁极数与磁极对数不是同一个数。
- 8 极电机通常是 4 对极。
- 磁极对数填错会让实际机械转速与预期不一致。

## 5.5 位置单位

```text
1 个位置单位 = 0.01°
```

换算：

```text
发送整数 = 目标角度° × 100
目标角度° = 接收整数 ÷ 100
```

示例：

|   角度 |   整数 | 数据            |
| -----: | -----: | --------------- |
|    0° |      0 | `00 00 00 00` |
|    5° |    500 | `00 00 01 F4` |
|   10° |   1000 | `00 00 03 E8` |
|   90° |   9000 | `00 00 23 28` |
|  360° |  36000 | `00 00 8C A0` |
| -360° | -36000 | `FF FF 73 60` |

## 6. 控制命令总表

以下假设 CAN ID 为 `001`。

| Data[0] | 名称               | 参数类型 | 单位/范围     | DLC |
| ------: | ------------------ | -------- | ------------- | --: |
|  `00` | 心跳               | 无       | 周期发送      |   1 |
|  `01` | 设定电流           | int16    | 10 mA         |   3 |
|  `02` | 设定转速           | int32    | erpm          |   5 |
|  `03` | 设定占空比         | int16    | -1000~1000    |   3 |
|  `04` | 绝对位置           | int32    | 0.01°        |   5 |
|  `05` | 相对上一个目标位置 | int32    | 0.01°        |   5 |
|  `06` | 相对当前位置       | int32    | 0.01°        |   5 |
|  `07` | 设定当前位置       | int32    | 0.01°        |   5 |
|  `08` | 刹车电流           | int16    | 10 mA，仅正值 |   3 |
|  `09` | 手刹电流           | int16    | 10 mA，仅正值 |   3 |
|  `0A` | 速度环加速度       | int32    | erpm/s²      |   5 |
|  `0B` | 轨迹位置最大速度   | int32    | erpm          |   5 |
|  `0C` | 轨迹位置最大加速度 | int32    | erpm/s²      |   5 |
|  `0D` | 轨迹位置最大减速度 | int32    | erpm/s²      |   5 |
|  `0E` | 切换电机配置表     | uint8    | 索引 0~3      |   2 |
|  `0F` | 查询指令           | 子命令   | 见第 8 章     |   2 |
|  `10` | 速度环减速度       | int32    | erpm/s²      |   5 |

重要：

> `0x01~0x0E`、`0x10` 等控制指令本身无专门应答。
> 要确认执行结果，应继续发送 `0x0F` 查询命令或开启上位机异步回传。

# 7. 各控制指令详解

## 7.1 心跳：`0x00`

### 作用

心跳用于证明主控仍在线。

如果驱动器配置了通信超时保护，而心跳停止更新，驱动器会进入安全状态并放空电机，控制命令可能无法继续正常执行。

### 发送帧

```text
CAN ID：001
DLC   ：1
Data  ：00
```

字段：

```text
Data[0] = 00，心跳
```

### 推荐周期

若上位机中设置心跳超时为：

```text
1000 ms
```

工程上可按约一半时间发送：

```text
500 ms 一次
```

机器人底盘通常可设置更短的安全超时和更快的心跳周期，但必须结合总线负载、控制周期和安全要求。

### 成功判断

心跳命令无独立返回。可通过以下方法间接验证：

```text
1. 持续心跳时，控制命令能够工作。
2. 停止心跳超过超时时间后，输出被撤销。
3. 查询故障或状态，确认没有通信超时相关异常。
```

### 常见误区

- 只在启动时发送一次心跳是不够的。
- 心跳应独立于速度/位置控制线程。
- 即使目标值不变，也要持续发送心跳。
- 多台驱动器需要分别向各自 CAN ID 发送心跳。

---

## 7.2 电流控制：`0x01`

### 作用

电流控制属于恒扭矩控制。

一般情况下：

```text
正电流 → 一个方向转动
负电流 → 相反方向转动
```

实际正反方向取决于电机相线、传感器方向和学习结果。

### 例 1：+1 A

```text
CAN ID：001
DLC   ：3
Data  ：01 00 64
```

解析：

```text
01      电流控制
00 64   int16 = 100
100 × 10 mA = 1 A
```

### 例 2：-1 A

```text
CAN ID：001
DLC   ：3
Data  ：01 FF 9C
```

解析：

```text
FF 9C = int16 -100
-100 × 10 mA = -1 A
```

### 例 3：首次小电流测试 0.2 A

```text
CAN ID：001
DLC   ：3
Data  ：01 00 14
```

### 停止/撤销输出

```text
CAN ID：001
DLC   ：3
Data  ：01 00 00
```

### 成功判断

控制指令无直接返回。可查询：

```text
电机电流：0F 05
总线电流：0F 06
当前转速：0F 01
故障信息：0F 00
```

### 风险

- MINI 持续电流为 4 A、最大电流为 8 A，但实际安全值还受电机、线材、散热和配置限制。
- 首次测试不要直接发 4 A 或 8 A。
- 电机堵转时仍可能产生较大扭矩与发热。
- 应先架空轮子或脱开机构。

---

## 7.3 转速控制：`0x02`

### 作用

速度闭环会尽量保持目标转速。

```text
正值 → 正转
负值 → 反转
```

驱动器使用 `erpm`，必须结合磁极对数换算。

### 示例条件

```text
磁极对数：4
机械目标：1000 rpm
目标电角速度：1000 × 4 = 4000 erpm
```

### 例 1：+1000 rpm

```text
CAN ID：001
DLC   ：5
Data  ：02 00 00 0F A0
```

### 例 2：-1000 rpm

```text
CAN ID：001
DLC   ：5
Data  ：02 FF FF F0 60
```

### 设置速度加速度

目标机械加速度：

```text
500 rpm/s²
```

4 对极转换为：

```text
500 × 4 = 2000 erpm/s²
```

发送：

```text
CAN ID：001
DLC   ：5
Data  ：0A 00 00 07 D0
```

### 设置速度减速度

目标机械减速度：

```text
200 rpm/s²
```

4 对极转换为：

```text
200 × 4 = 800 erpm/s²
```

发送：

```text
CAN ID：001
DLC   ：5
Data  ：10 00 00 03 20
```

### 完整速度控制顺序

```text
1. 持续发送心跳
   ID 001  DLC 1  Data 00

2. 设置加速度 2000 erpm/s²
   ID 001  DLC 5  Data 0A 00 00 07 D0

3. 设置减速度 800 erpm/s²
   ID 001  DLC 5  Data 10 00 00 03 20

4. 设置目标速度 4000 erpm
   ID 001  DLC 5  Data 02 00 00 0F A0
```

### 停止

可使用：

```text
ID 001  DLC 5  Data 02 00 00 00 00
```

使目标速度降为 0。

也可发送：

```text
ID 001  DLC 3  Data 01 00 00
```

撤销电流输出。

两者效果不同：

```text
速度目标 0：速度环尝试把速度控制到 0。
电流目标 0：切入 0 电流输出，通常更接近放空/失能。
```

### 成功判断

查询当前转速：

```text
CAN ID：001
DLC   ：2
Data  ：0F 01
```

返回示例：

```text
CAN ID：001
DLC   ：6
Data  ：0F 01 00 00 13 88
```

解析：

```text
00 00 13 88 = 5000 erpm
若磁极对数为 4：
5000 ÷ 4 = 1250 rpm
```

## 7.4 占空比控制：`0x03`

### 作用

占空比范围：

```text
-1000 ~ +1000
```

对应：

```text
-100% ~ +100%
```

示例：

```text
100 → +10%
-100 → -10%
```

### +10%

```text
CAN ID：001
DLC   ：3
Data  ：03 00 64
```

### -10%

```text
CAN ID：001
DLC   ：3
Data  ：03 FF 9C
```

### 与速度控制的区别

占空比控制不会像速度闭环那样主动补偿负载。

一般表现为：

```text
负载变大 → 转速下降
负载变小 → 转速上升
```

### 首次测试建议

```text
从 ±50 或 ±100 开始
不要直接发送 ±1000
```

---

## 7.5 绝对位置控制：`0x04`

### 作用

绝对位置是相对于驱动器当前零点的全局位置。

例如：

```text
目标 36000
单位 0.01°
= 360°
= 相对零点正向 1 圈
```

### 设置位置轨迹参数

最大速度：

```text
CAN ID：001
DLC   ：5
Data  ：0B 00 00 13 88
```

含义：

```text
最大速度 = 5000 erpm
```

加速度：

```text
CAN ID：001
DLC   ：5
Data  ：0C 00 00 13 88
```

减速度：

```text
CAN ID：001
DLC   ：5
```

## 7.6 相对上一个目标位置：`0x05`

### 作用

该命令不是相对电机“当前实际位置”，而是相对**上一次目标位置**。

例：

```text
上一次目标：36000
电机尚未到达
再次发送相对上一个目标 +36000
最终目标：72000
```

### +360°

```text
CAN ID：001
DLC   ：5
Data  ：05 00 00 8C A0
```

### -360°

```text
CAN ID：001
DLC   ：5
Data  ：05 FF FF 73 60
```

### 适用场景

- 队列式位置增量
- 连续步进
- 主控以目标值为基准累加

### 风险

若上一次目标尚未完成，新的增量仍会加到**旧目标值**上，而不是当前位置上。

## 7.7 相对当前位置：`0x06`

### 作用

该命令以驱动器收到指令时的当前实际位置为基准。

### +360°

```text
CAN ID：001
DLC   ：5
Data  ：06 00 00 8C A0
```

### -360°

```text
CAN ID：001
DLC   ：5
Data  ：06 FF FF 73 60
```

### 与 `0x05` 的区别

```text
0x05：相对上一个目标位置
0x06：相对当前实际位置
```

举例：

```text
当前实际位置：10000
上一次目标位置：36000
增量：+5000

0x05 最终目标：41000
0x06 最终目标：15000
```

## 7.8 设定当前位置 / 设置零点：`0x07`

### 作用

把当前机械位置重新定义为指定的位置值。

最常见用途：

```text
把当前位置定义为 0
```

### 设置当前位置为零点

```text
CAN ID：001
DLC   ：5
Data  ：07 00 00 00 00
```

### 注意

这条指令的含义是：

```text
“把现在所在位置的坐标改成 0”
```

不是：

```text
“让电机自动转回零点”
```

### 推荐流程

```text
1. 让电机停止。
2. 确认机构没有受力和干涉。
3. 手动或低速移动到机械基准。
4. 发送 07 00 00 00 00。
5. 查询位置 0F 08。
6. 确认位置接近 0。
```

## 7.9 刹车控制：`0x08`

### 作用

这是电子刹车。

刹车强度与刹车电流相关，且实际刹车效果也与当前转速有关。

仅正值有效。

### 1 A 刹车

```text
CAN ID：001
DLC   ：3
Data  ：08 00 64
```

### 0.2 A 小刹车测试

```text
CAN ID：001
DLC   ：3
Data  ：08 00 14
```

### 再生制动风险

刹车会把机械能回馈到直流母线，使母线电压升高。

如果使用：

```text
普通开关电源
```

电源通常不能吸收回馈电流，可能造成：

```text
母线过压
驱动器过压保护
电源损坏
驱动器损坏
```

解决方式包括：

```text
制动电阻/斩波器
能量耗散单元
能够吸收回馈的电源
电池供电系统
降低刹车电流和减速度
```

---

## 7.10 手刹控制：`0x09`

### 作用

手刹通过强行对准某个电角度形成锁止效果。

仅正值有效。

### 1 A 手刹

```text
CAN ID：001
DLC   ：3
Data  ：09 00 64
```

### 强制安全规则

> 手刹只能在极低速或 0 速时使用。

高速使用可能损坏：

```text
电机
MOS 管
驱动器
机械结构
```

推荐：

```text
1. 先把目标速度设为 0。
2. 查询当前速度确认接近 0。
3. 再使用较小手刹电流。
4. 监测驱动器温度与电流。
```

## 7.15 切换电机配置表：`0x0E`

MINI 驱动器内部可保存 4 份电机配置。

有效索引：

```text
0、1、2、3
```

CAN 指令使用从 0 开始的索引：

| Data[1] | 人类理解    |
| ------: | ----------- |
|  `00` | 第 1 份配置 |
|  `01` | 第 2 份配置 |
|  `02` | 第 3 份配置 |
|  `03` | 第 4 份配置 |

### 切到第 2 份配置

```text
CAN ID：001
DLC   ：2
Data  ：0E 01
```

### 重要

- 配置表必须先通过欧艾迪上位机完成电机学习和参数保存。
- CAN 切换本身掉电不保存。
- 切换前应停止电机。
- 不要在控制循环中频繁切换。
- 不同配置可能对应不同电机或完全不同 PID/传感器设置，误切可能造成危险。

# 8. 查询指令：`0x0F`

## 8.1 查询帧结构

```text
CAN ID：驱动器 ID
DLC   ：2
Data  ：0F [查询子命令]
```

驱动器返回时：

```text
CAN ID：通常仍为该驱动器 ID
Data[0]：0F
Data[1]：原查询子命令
Data[2...]：返回数据
```

## 8.2 查询指令总表

| 子命令 | 查询内容             | 请求 Data | 典型返回 DLC | 返回值                       |
| -----: | -------------------- | --------- | -----------: | ---------------------------- |
| `00` | 故障信息             | `0F 00` |            4 | 故障码                       |
| `01` | 当前转速             | `0F 01` |            6 | int32，erpm                  |
| `02` | 当前占空比           | `0F 02` |            4 | int16，-1000~1000            |
| `03` | 当前功率             | `0F 03` |            4 | uint16，W                    |
| `04` | 母线电压             | `0F 04` |            4 | uint16，V                    |
| `05` | 电机电流             | `0F 05` |            4 | int16，10 mA                 |
| `06` | 总线电流             | `0F 06` |            4 | int16，10 mA                 |
| `07` | 驱动器温度           | `0F 07` |            4 | uint16，℃                   |
| `08` | 多圈位置信息         | `0F 08` |            6 | int32，0.01°                |
| `09` | 单圈角度             | `0F 09` |            4 | uint16，0.01°               |
| `0A` | 编码器模式是否找到 Z | `0F 0A` |            3 | 0/1                          |
| `0B` | 缓存错误             | `0F 0B` |            7 | Data[2]~Data[6] 原始错误缓存 |

# 9. 故障码解释

MINI 产品手册给出的错误灯闪烁次数和故障信息如下。同步查询 `0F 00` 返回非零时，可结合该表判断。

| 故障码 | 含义                   |
| -----: | ---------------------- |
|      0 | 无错误                 |
|      1 | 过压                   |
|      2 | 欠压                   |
|      3 | 绝对值超过最大电流     |
|      4 | MOS 管过温             |
|      5 | MCU 欠压               |
|      6 | 看门狗触发后启动       |
|      7 | SPI 接口驱动器错误     |
|      8 | FLASH 损毁             |
|      9 | U 相电流传感器偏移过大 |
|     10 | V 相电流传感器偏移过大 |
|     11 | W 相电流传感器偏移过大 |
|     12 | 三相电流不平衡         |
|     13 | FLASH 中电机配置损毁   |
|     14 | FLASH 中应用配置损毁   |
|     15 | CANopen 心跳错误       |
|     16 | 堵转                   |
|     17 | 失速                   |
|     18 | 超差                   |
|     19 | 编码器未找到 Z 信号    |

### 9.1 故障处理固定流程

```text
1. 停止发送运动目标。
2. 发送 0 A：
   ID 001  DLC 3  Data 01 00 00
3. 查询故障：
   ID 001  DLC 2  Data 0F 00
4. 查询电压、温度和电流。
5. 排除真实故障原因。
6. 必要时使用欧艾迪上位机重启或重新写入配置。
7. 重新上电后，先只发心跳和查询。
8. 再用小目标测试。
```

注意：

- 查询到错误并不代表发送“清零数据”就能修复。
- 产品手册有上位机“重启”按钮，但现有标准 CAN 控制命令表没有给出独立 CAN 重启或清故障帧，因此不要凭空构造此类命令。

## 10.2 第 2 阶段：0.2 A 小电流测试

# 11. DMTool 发送与接收怎么看

## 11.1 “发送成功”只说明什么

DMTool 显示：

```text
发送成功
```

通常只说明：

```text
电脑 → USB-CAN 适配器 → 发送队列
```

没有被软件判定为失败。

它不能单独证明：

```text
驱动器收到帧
驱动器 ID 正确
驱动器执行了目标
心跳有效
电机没有故障
电机真的转到目标
```

## 11.2 控制命令为什么没有对应返回

欧艾迪标准 CAN 资料明确说明控制指令无返回。

例如发送：

```text
ID 001
DLC 3
Data 01 00 64
```

不能等待一条“电流设置成功”的专门应答。

应主动查询：

```text
0F 05：电机电流
0F 01：转速
0F 08：位置
0F 00：故障
```

## 11.3 查询请求与返回怎样配对

例如：

```text
发送：
ID 001  DLC 2  Data 0F 04

接收：
ID 001  DLC 4  Data 0F 04 00 30
```

配对依据：

```text
CAN ID 相同
Data[0] 都是 0F
Data[1] 都是 04
时间戳相近
```

## 11.4 多台驱动器时怎样区分

假设：

```text
左前轮 ID：001
右前轮 ID：002
左后轮 ID：003
右后轮 ID：004
```

查询各自转速：

```text
ID 001  Data 0F 01
ID 002  Data 0F 01
ID 003  Data 0F 01
ID 004  Data 0F 01
```

返回 CAN ID 就能区分来源。

| 右前驱动 | `0x002` |
| 左后驱动 | `0x003` |
| 右后驱动 | `0x004` |
| 左前转向 | `0x011` |
| 右前转向 | `0x012` |
| 左后转向 | `0x013` |
| 右后转向 | `0x014` |

不要让两台驱动器使用相同 CAN ID。

## 12.2 心跳调度

每台驱动器都需要收到自己的心跳：

```text
001 / 00
002 / 00
003 / 00
004 / 00
```

可以在一个定时任务中轮询发送。

## 12.3 控制周期

底盘控制常见设计：

```text
心跳线程：独立周期
目标速度线程：按底盘控制频率发送
状态查询线程：分散轮询，避免瞬间占满总线
故障线程：收到异常立即撤销所有电机输出
```

## 12.4 急停逻辑

软件急停可对所有驱动器依次发送：

```text
01 00 00
```

即 0 A。

若需要更快或更可靠的安全停机，还应有：

```text
硬件急停
主电源接触器
制动电阻/能量吸收
主控看门狗
CAN 超时保护
```

软件 CAN 命令不能代替硬件急停。

# 13. STM32 C 语言组帧参考

以下代码只负责数据组帧和解析。CAN 外设初始化、邮箱发送和过滤器需要按 STM32 型号补充。

```c
#include <stdint.h>
#include <stddef.h>

typedef struct {
    uint16_t std_id;
    uint8_t dlc;
    uint8_t data[8];
} OidCanFrame;

static void oid_put_i16_be(uint8_t *dst, int16_t value)
{
    uint16_t raw = (uint16_t)value;
    dst[0] = (uint8_t)(raw >> 8);
    dst[1] = (uint8_t)(raw);
}

static void oid_put_i32_be(uint8_t *dst, int32_t value)
{
    uint32_t raw = (uint32_t)value;
    dst[0] = (uint8_t)(raw >> 24);
    dst[1] = (uint8_t)(raw >> 16);
    dst[2] = (uint8_t)(raw >> 8);
    dst[3] = (uint8_t)(raw);
}

static int16_t oid_get_i16_be(const uint8_t *src)
{
    uint16_t raw = ((uint16_t)src[0] << 8)
                 | ((uint16_t)src[1]);
    return (int16_t)raw;
}

static int32_t oid_get_i32_be(const uint8_t *src)
{
    uint32_t raw = ((uint32_t)src[0] << 24)
                 | ((uint32_t)src[1] << 16)
                 | ((uint32_t)src[2] << 8)
                 | ((uint32_t)src[3]);
    return (int32_t)raw;
}

static OidCanFrame oid_make_heartbeat(uint16_t motor_id)
{
    OidCanFrame frame = {0};
    frame.std_id = motor_id;
    frame.dlc = 1;
    frame.data[0] = 0x00;
    return frame;
}

static OidCanFrame oid_make_current(uint16_t motor_id, float current_a)
{
    OidCanFrame frame = {0};

    float scaled = current_a * 100.0f;
    if (scaled > 32767.0f) scaled = 32767.0f;
    if (scaled < -32768.0f) scaled = -32768.0f;

    int16_t command = (int16_t)scaled;

    frame.std_id = motor_id;
    frame.dlc = 3;
    frame.data[0] = 0x01;
    oid_put_i16_be(&frame.data[1], command);
    return frame;
}

static OidCanFrame oid_make_speed_erpm(
    uint16_t motor_id,
    int32_t speed_erpm)
{
    OidCanFrame frame = {0};
    frame.std_id = motor_id;
    frame.dlc = 5;
    frame.data[0] = 0x02;
    oid_put_i32_be(&frame.data[1], speed_erpm);
    return frame;
}

static OidCanFrame oid_make_speed_rpm(
    uint16_t motor_id,
    int32_t mechanical_rpm,
    uint16_t pole_pairs)
{
    int32_t erpm = mechanical_rpm * (int32_t)pole_pairs;
    return oid_make_speed_erpm(motor_id, erpm);
}

static OidCanFrame oid_make_abs_position_deg(
    uint16_t motor_id,
    float position_deg)
{
    OidCanFrame frame = {0};

    float scaled = position_deg * 100.0f;
    int32_t position_raw = (int32_t)scaled;

    frame.std_id = motor_id;
    frame.dlc = 5;
    frame.data[0] = 0x04;
    oid_put_i32_be(&frame.data[1], position_raw);
    return frame;
}

static OidCanFrame oid_make_query(
    uint16_t motor_id,
    uint8_t subcommand)
{
    OidCanFrame frame = {0};
    frame.std_id = motor_id;
    frame.dlc = 2;
    frame.data[0] = 0x0F;
    frame.data[1] = subcommand;
    return frame;
}
```

## 13.1 查询返回解析示例

```c
typedef struct {
    int valid;
    uint8_t subcommand;
    int32_t signed_value;
    uint32_t unsigned_value;
} OidQueryResult;

static OidQueryResult oid_parse_query(
    uint16_t expected_id,
    uint16_t rx_id,
    uint8_t dlc,
    const uint8_t data[8])
{
    OidQueryResult result = {0};

    if (data == NULL || rx_id != expected_id || dlc < 2) {
        return result;
    }

    if (data[0] != 0x0F) {
        return result;
    }

    result.subcommand = data[1];

    switch (data[1]) {
    case 0x00: /* fault */
    case 0x02: /* duty */
    case 0x03: /* power */
    case 0x04: /* voltage */
    case 0x05: /* motor current */
    case 0x06: /* bus current */
    case 0x07: /* temperature */
    case 0x09: /* single-turn angle */
        if (dlc >= 4) {
            int16_t v = oid_get_i16_be(&data[2]);
            result.signed_value = v;
            result.unsigned_value =
                ((uint16_t)data[2] << 8) | data[3];
            result.valid = 1;
        }
        break;

    case 0x01: /* speed */
    case 0x08: /* multi-turn position */
        if (dlc >= 6) {
            int32_t v = oid_get_i32_be(&data[2]);
            result.signed_value = v;
            result.unsigned_value = (uint32_t)v;
            result.valid = 1;
        }
        break;

    case 0x0A: /* Z found */
        if (dlc >= 3) {
            result.unsigned_value = data[2];
            result.signed_value = data[2];
            result.valid = 1;
        }
        break;

    default:
        break;
    }

    return result;
}
```

# 16. 收不到反馈时按此顺序排查

## 16.1 帧格式错误

必须是：

```text
11 位标准数据帧
```

不是：

```text
29 位扩展帧
```

## 16.2 CAN ID 错误

CAN ID 是驱动器地址。

例如驱动器 ID 为 1：

```text
正确：001
错误：0300FD01
错误：201
错误：把 01 只写进 Data 而 CAN ID 填 0
```

## 16.3 波特率不一致

DMTool、STM32、USB-CAN 和所有驱动器必须使用相同波特率。

本文不假设出厂默认波特率，应以欧艾迪上位机中写入的 CAN 配置为准。

## 16.4 DLC 错误

欧艾迪命令 DLC 不是固定 8。

例如：

```text
心跳：1
查询：2
电流：3
速度：5
位置：5
转速返回：6
```

## 16.5 字节序错误

正确：

```text
100 = 00 64
4000 = 00 00 0F A0
```

错误：

```text
100 = 64 00
4000 = A0 0F 00 00
```

## 16.6 未持续发送心跳

即使控制帧完全正确，若心跳超时保护已经启用，而主控没有持续发送 `00`，驱动器仍可能放空电机。

## 16.7 应用类型没有切到 CAN 总线

只连接 CAN 线不代表驱动器已经接受 CAN 控制。

应通过 Type-C 上位机写入：

```text
应用类型 = CAN 总线
```

## 16.8 控制命令无返回被误判为故障

控制命令本来就无专门应答。

应使用 `0F xx` 查询结果。

## 16.9 电机未正确学习

若相线、霍尔、ABZ 或传感器模式改变，需重新学习电机。

产品手册说明：

- U/V/W 相线顺序改变后要重新学习；
- 霍尔 HU/HV/HW 顺序改变后要重新学习；
- ABZ 模式每次启动需要识别到 Z 信号。

## 16.10 终端电阻、线序和信号地

检查：

```text
CAN 差分线是否接反
主干两端是否有终端
是否并联过多终端电阻
线缆是否过长
支线是否过长
是否共地
接头是否松动
```

## 16.11 使用了 CANopen 模式

欧艾迪 MINI 同时支持 CAN 和 CANopen。

若驱动器当前设置为 CANopen，本文的：

```text
ID 001 / Data 01 00 64
```

不会按本文含义执行。

# 17. 最终检查清单

发送前确认：

```text
[ ] 驱动器已完成电机学习
[ ] 应用类型已设置为 CAN 总线
[ ] 使用的是标准 CAN，不是 CANopen
[ ] CAN ID 已确认
[ ] CAN 波特率已确认
[ ] 心跳超时时间已确认
[ ] CAN 分析仪选择 11 位标准帧
[ ] 帧类型选择数据帧
[ ] DLC 按命令填写，不固定为 8
[ ] 多字节整数按高字节在前
[ ] 负数按二进制补码
[ ] erpm 已按磁极对数换算
[ ] 位置单位按 0.01° 换算
[ ] 电流单位按 10 mA 换算
[ ] 控制前持续发送心跳
[ ] 首次运动已架空轮子或脱开机构
[ ] 已准备 0 A 停止帧
[ ] 电子刹车已考虑母线回馈能量
[ ] 手刹只在低速或 0 速使用
[ ] 多台驱动器 CAN ID 不冲突
[ ] 有硬件急停，不只依赖软件命令
```
